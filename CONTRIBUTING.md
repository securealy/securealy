# Contributing

Thanks for helping make launches safer. Two rules keep this project honest.

## 1. New checks start in `checks.json`

`packages/checks/checks.json` is the contract. A check does not exist until it has an entry there with every field filled in: `id` (kebab-case, stable forever), `category`, `title`, `severity`, `tier`, `what` (one sentence, what passing means), `why` (one sentence), `module` and `freeFix`. Pick the severity by what happens when the check fails, not by how hard the fix is: a `blocker` is something a customer or an attacker hits on day one.

Never rename or reuse an id. Results are stored against ids for years.

## 2. Every check needs a fixture pair

Each remote check is a module in `packages/core/src/checks/<id>.ts` exporting `{ id, run(ctx) }`. It reads the evidence the fetcher gathered and nothing else: no fetching, no randomness, no clock. The same evidence must always give the same result.

Each check needs `packages/core/test/fixtures/<id>/pass.json` and `fail.json`, both serialized `Evidence` objects. The remote fixtures are generated by `packages/core/test/tools/make-fixtures.mjs`: add a case to its table, run `npm run build && npm run fixtures`, and commit the JSON. The local checks (`packages/core/src/local/<id>.ts`) use scenario fixtures instead: files to create, whether to initialise git, the env to expose and canned HTTP responses.

`npm test` runs every pair and fails if a check lacks one.

## Evidence rules

- Evidence strings are short, human readable, and never contain a response body.
- Anything that looks like a secret is redacted at the source to six characters plus an ellipsis. `result()` in `checks/context.ts` runs the redactor over every evidence string as a last line of defence; do not bypass it.
- Use `skip` when a check does not apply (and say why), `error` when it could not run, `warn` when the finding is real but partial or low confidence.

## Passive means passive

A passive check may only use evidence that a browser visiting the site would produce. If a check needs a request that an owner would not want run against a stranger's site, it belongs in the `verified` tier.

## Before you open a pull request

```
npm run build && npm test && npm run lint
```

All three must be clean. No warnings.
